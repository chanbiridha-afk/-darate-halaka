# منصة إدارة حلقة تحفيظ القرآن الكريم
### المدرسة النموذجية النهضة بالقرآن الكريم

منصة رقمية سحابية (مبنية على Firebase) لإدارة حلقة تحفيظ القرآن الكريم: تسجيل المتعلمين وتفويجهم،
السنوات الدراسية، تسجيل جلسات الحفظ/المراجعة/التلاوة/الأربعين النووية/الأذكار، الاختبارات والفروض
والتقويم المستمر، كشوف النتائج الفصلية القابلة للطباعة، متابعة اشتراكات المتعلمين، وبوابة مستقلة
لأولياء الأمور لمتابعة أبنائهم عن بُعد.

---

## 1. الأدوار الثلاثة

| الدور | كيف يُنشأ الحساب | الصلاحيات |
|---|---|---|
| **المدير الإداري** (مسيّر المدرسة) | يسجّل بنفسه عبر "إنشاء حساب" ثم "مدير إداري"، ويحتاج **رمز الدعوة** | صلاحيات كاملة: السنوات، الأفواج، تسجيل المتعلمين وتفويجهم، حسابات المعلمين، الاشتراكات، كل المسارات والتقارير |
| **المعلّم / مشرف الحلقة** | **لا يسجّل نفسه**؛ ينشئ له المدير الإداري الحساب من صفحة "حسابات المعلّمين" ويُسند إليه فوجًا أو أكثر | تسجيل الجلسات والاختبارات لمتعلمي أفواجه المسندة فقط؛ لا يرى/يعدّل بيانات المتعلمين أو الاشتراكات |
| **ولي الأمر** | يسجّل بنفسه عبر "إنشاء حساب" ثم "ولي أمر"، ثم يربط حسابه بابنه عبر **الرقم التعريفي** + **تاريخ الميلاد** | عرض للقراءة فقط: تقدّم ابنه، الحضور، نتائج الاختبارات، حالة الاشتراك |

رمز دعوة المدير الإداري مضبوط افتراضيًا على `NAHDA-2026`. لتغييره: افتحوا `firebase-init.js` وعدّلوا قيمة `ADMIN_INVITE_CODE`.

---

## 2. خطوات إعداد Firebase (مرّة واحدة فقط)

1. **تفعيل تسجيل الدخول بالبريد**: Firebase Console → Authentication → Sign-in method → فعّلوا Email/Password (إن لم يكن مفعّلًا).
2. **إنشاء قاعدة البيانات**: Build → Firestore Database → Create database (إن لم تُنشأ من قبل).
3. **نشر قواعد الأمان (خطوة ضرورية)**: افتحوا ملف `firestore.rules.txt` المرفق، انسخوا محتواه بالكامل، وألصقوه في:
   Firebase Console → Firestore Database → Rules → ثم اضغطوا **Publish**.
   بدون هذه الخطوة، لن تعمل صلاحيات الأدوار الثلاثة بشكل صحيح.

---

## 3. أول استخدام

1. افتحوا التطبيق (بعد رفعه على Netlify/GitHub Pages أو تشغيله محليًا) → "إنشاء حساب جديد" → **مدير إداري** → أدخلوا رمز الدعوة `NAHDA-2026`.
2. من حساب المدير: أنشئوا **سنة دراسية** أولًا (صفحة "السنوات الدراسية")، ثم **الأفواج**، ثم سجّلوا **المتعلمين** وأسندوهم للأفواج.
3. من صفحة "حسابات المعلّمين": أنشئوا حساب معلّم لكل مشرف حلقة، وأسندوا له الفوج/الأفواج المناسبة، وشاركوا معه بريده وكلمة المرور المؤقتة.
4. كل متعلّم يحصل تلقائيًا على **رقم تعريفي** (مثل `NHD-482913`) يظهر في بطاقته — شاركوه مع ولي الأمر ليستخدمه عند إنشاء حسابه.

---

## 4. النشر (Netlify / GitHub Pages)

نفس الطريقة المعتادة: ارفعوا مجلد المشروع كما هو (لا حاجة لأي أمر بناء build).
ملف `netlify.toml` مُجهَّز مسبقًا. تأكدوا من رفع كل الملفات بما فيها `firebase-init.js`، `auth.js`، `store.js`.

---

## 5. ملاحظات وحدود معروفة

- **رمز دعوة المدير** تحقق من جهة العميل (Client-side) فقط؛ وهذا كافٍ لسياق مدرسة صغيرة موثوقة، لكنه ليس حماية على مستوى الخادم. لحماية أقوى مستقبلًا يمكن الانتقال إلى Cloud Functions.
- لتمكين ولي الأمر من البحث عن ابنه بالرقم التعريفي عند الربط الأول، تسمح قواعد الأمان لأي "ولي أمر" مسجَّل بقراءة بيانات المتعلمين (وليس التعديل عليها). الرقم التعريفي + تاريخ الميلاد يشكّلان تحققًا ثنائيًا كافيًا لهذا السياق.
- استعلامات "أفواج المعلّم" تدعم حتى ٣٠ فوجًا/متعلمًا في القائمة الواحدة (حد Firestore)، وهو أكثر من كافٍ لحلقة عادية.
- جميع البيانات مُزامنة سحابيًا لحظيًا (Firestore)؛ لا حاجة لأي نسخ احتياطي يدوي، لكن يُنصح بمراجعة نسخة `firestore.rules.txt` بعد أي تعديل مستقبلي في الأدوار.

---

## 6. المسارات الست في تسجيل الجلسة

الحفظ (سورة/آية برواية ورش المعتمدة على مجمع الملك فهد) · المراجعة (قريب/بعيد) · التلاوة النظرية (تحفة الأطفال) ·
التلاوة التطبيقي (جيدة/متوسطة/ضعيفة) · الأربعون النووية (٤٢ حديثًا بنصوصها) · الأذكار (٢١ بابًا مع الدليل).
